GapKeep

A tiny bare-metal OS for air‑gapped apps.

GapKeep turns a Raspberry Pi Zero, the plain one with no radio, into a computer that boots in about two seconds, keeps nothing, and lets data cross only where you can see it. Made for secrets: Bitcoin keys first, and much more.

01Small is beautiful

One small computer, one job: handling secrets offline.

No Linux, no network stack, no drivers for anything but a screen, a keyboard, a mouse and a camera. GapKeep is one program for the Pi Zero that starts straight into a JavaScript runtime with a graphical interface. Small enough to read, quick to start, and built so that you can check what runs.

Boots in about two seconds

Power on, and the launcher is up in about two seconds. Apps start at once; there is nothing else to load.

Decent on a $5-class computer

One ARM core and 512 MB are enough to explain and sign a Bitcoin transaction on the device. Deriving a key from a seed phrase takes about a tenth of a second.

Amnesiac: nothing is saved

GapKeep never writes to its SD card. What an app holds is wiped when it closes, and everything is gone at power-off.

The card can come out

The SD card is read once, at boot. Once the launcher is up, you can take the card out and keep it elsewhere; everything keeps working until power-off.

Generic, not just crypto

Apps are small JavaScript programs. Bitcoin came first, but an authenticator, a clock and a REPL already ship, and more is planned.

In the eighties, all computers were air‑gapped.

GapKeep brings a little of that back, on purpose.

02See it, check it

What matters happens where you can see it.

Security that depends on trusting a box is hard to check. GapKeep shows its work instead: where the randomness in your keys comes from, every bit of data that crosses the gap, and the code that is running. Each can be checked by a person, with their own eyes.

Entropy you can see

Your seed comes from dice you threw yourself.

A key is only as good as its randomness, and a chip's randomness can't be seen. dice39 makes BIP-39 seed phrases from real dice and a coin: you roll, look up the word in a printed table, and type it. The device fills in the remaining words from its hardware random generator, mixed with your own taps, and computes the checksum.

  • The words you rolled are kept verbatim, and the screen marks which came from you and which from the device.
  • What you type is checked as you go, and likely mistakes are pointed out, never silently fixed.
  • Then split it into codex32 shares, to keep in different places.

Every message, in the open

What crosses the gap is a QR code you can read.

A transaction prepared by an online wallet arrives as a QR code. The Signer shows what it does before any key is in memory: what is sent, to which addresses, the fee, and which outputs only claim to be your change until a key proves it. You sign; the result leaves as a QR code on the screen, which your wallet reads back.

  • No cable, no file, no hidden channel: only codes you can see, and decode with any phone if you want to check.
  • Addresses are grouped by four characters, to compare with the receiver's.
  • Warnings come in colours: red means don't sign; amber, check.

Code you can check

What runs has a hash, and the hash is on the screen.

The launcher shows the SHA-256 of every app, and it covers every line of JavaScript the app runs: apps never share code at run time. The kernel shows the hash of its own code. GapKeep's builds are reproducible: the same commit gives the same kernel, byte for byte, wherever it is built. So the hashes on your screen can be compared with published ones.

The security model, in detail

03Amnesiac by design

Your keys don't live here. They visit.

GapKeep stores no key, encrypted or otherwise. Keys live elsewhere: on paper, as seed words, or split into codex32 shares kept in different places, where no single share is the key. When a task needs one, you bring the shares in, typed or shown to the camera. GapKeep recombines them in memory, does the task, and forgets them.

  1. Bring the sharesTyped in groups of four, as written, or scanned. Each is checked as you type.
  2. Recombine in memoryEnough shares make the key again, for this task only.
  3. Do the taskSign a transaction, show a public key, recover the words.
  4. ForgetKeys are wiped; freed memory is zeroed. At power-off nothing is left.

Lose it, and nothing is lost.A switched-off GapKeep holds no key: it can be lost, stolen or inspected without revealing one. What you must keep safe is something you can see and count: your shares, on paper.

04Apps

Bitcoin first. Not Bitcoin only.

Cryptocurrency is GapKeep's first use, and the most developed. But a computer that keeps secrets offline is useful for much more, and its apps are small programs anyone can write and read.

Bitcoin

Signer

Shows what a transaction does, then signs it. PSBTs from Electrum's QR codes; keys from codex32 shares, seed words, an xprv or a WIF. Checks change before calling it change.

Bitcoin

dice39

Seed phrases from dice you can see, with the device's randomness mixed in. Split them into codex32 shares, show SeedQR codes, export the public key.

Bitcoin

codex32

Recombines codex32 shares into the phrase. A mistyped character is caught, and the app says which one it probably is: you check it against the paper.

Beyond crypto

Authenticator

Two-factor codes (TOTP), as phone authenticators show them. Accounts by QR code or typed key; kept in memory only, until power-off.

Beyond crypto

Clock

A Pi Zero has no battery-backed clock. Set the time by hand against a reference, with a UTC offset and a trim for drift.

Beyond crypto

REPL

Type JavaScript on the device and see what it does, widgets included. A Bitcoin library is at hand, for experiments.

Tools

QR Scanner

Shows what a QR code holds, read with the same camera driver and decoder every app uses.

System

Settings

Language (English or Brazilian Portuguese), number format and keyboard layout, until power-off.

Planned

And next

A PGP suite, with public keys as data folders on the card. Perhaps even a little game: a computer this small should be fun too. Or your app.

05For developers

An app is a folder of JavaScript.

Apps run on QuickJS (modern JavaScript) and draw with LVGL through one module, gk:ui. Each runs alone, in its own runtime, and reaches the system only through the gk:* modules its manifest allows. Write it in the browser, run it in a simulator, put it on a card.

apps/hello/main.js
import * as ui from "gk:ui";

const label = new ui.Label({
  text: "Hello, air gap!",
  font: 28,
});
new ui.Button({
  text: "Click",
  onClick: () => (label.text = "Clicked!"),
});

06Hardware

What you need.

A Raspberry Pi Zero, a screen and a keyboard. Everything is off the shelf.

The minimum

  • 01
    Raspberry Pi Zero v1.3The plain Zero, with no wireless. Not the Zero W or Zero 2 W: they have radios.
  • 02
    A microSD cardFor GapKeep's image. It is only ever read.
  • 03
    An HDMI screen and a mini-HDMI cable or adapterThe Zero's video port is mini-HDMI.
  • 04
    A wired USB keyboard, and an OTG adapterMicro-USB (male) to USB-A (female), into the port marked USB, not PWR.
  • 05
    A micro-USB power supplyInto the port marked PWR.

Recommended

  • +
    Raspberry Pi Camera Module v2.1, with a Zero camera cableHighly recommended: for QR codes in and out. The Zero's camera connector is narrower than other Pis', so it needs the Zero's own ribbon cable, not the standard one that comes with the module. Other camera modules (1, 3, HQ) and USB cameras are not supported at this time.
  • +
    A wired mouse, and a small USB hubA mouse adds comfort, but isn't needed: every app works from the keyboard alone. A hub connects both to the one USB port.

Use a wired keyboard and mouse.A wireless keyboard puts a radio back on the most sensitive channel there is: everything you type. The point of a computer with no radio is lost if its keyboard talks over the air.

Why the plain Pi Zero?It has no Wi-Fi and no Bluetooth hardware at all: the air gap is in the hardware, not a setting someone could turn back on. GapKeep is built for, and tested on, the Pi Zero v1.3 with 512 MB.

07Security, honestly

What it is built to do, and what it can't.

GapKeep's goal is a machine on which secrets are created and handled with no way out but what a person reads off the screen. It is new and has not been audited by people yet: read this as design intent, and check it.

Designed in

  • No network, no radio. The Pi Zero has no radio hardware, and GapKeep has no network stack.
  • Little to attack. The USB drivers are cut down to hubs, keyboards and mice; production builds have no serial port driver.
  • A read-only card. Read once at boot, by a FAT driver built without its write code; never written.
  • A hardened QR decoder. Fuzzed with damaged and crafted codes; apps get the decoded text, never the pictures.
  • Memory protection. Code is read-only and the only executable memory; stack canaries and a stack guard; freed memory is zeroed.
  • Checkable builds. Reproducible, with a pinned compiler and firmware; the kernel and every app show their hashes.

Not protected against

  • A swapped card. Whoever can write the SD card can replace the kernel and the apps. Compare the hashes on the screen with published ones.
  • Physical attacks on a running device. A Pi Zero has no memory encryption: probing its RAM or bus while it runs is out of scope.
  • The Pi's closed boot firmware, which every system on the Pi depends on. It is pinned by hash.
  • Native-code exploits between apps. Apps run in separate JavaScript runtimes, but share one address space.
  • What anyone can see. Whatever is on the screen can be seen by whoever, or whatever camera, can see the screen.
  • Test builds and the simulator. Test builds log to the serial port by design; neither is for real secrets.

Found a problem? Please report it privately, through GitHub's private vulnerability reporting, never in a public issue. More in SECURITY and the security model.

08And SeedSigner?

If you only want Bitcoin, SeedSigner is great.

SeedSigner is an established open-source Bitcoin signing device, also built from a Raspberry Pi Zero and a camera, also air-gapped and stateless, with a community that has been at it for years. If a Bitcoin signer is all you need, we recommend it. GapKeep owes it a debt too: SeedQR, the QR code for seed phrases that dice39 and codex32 show, is SeedSigner's.

The two overlap a lot, and their scopes differ. SeedSigner is a Bitcoin signer. GapKeep is a small platform for air-gapped apps in general, with a story for developers; signing Bitcoin transactions is one of its apps.

09Questions

Frequently asked.

Why not Linux?

Linux is wonderful, and enormous: millions of lines, with networking, storage, radios and drivers for thousands of devices, all of which would have to be trusted or taken out. GapKeep needs a screen, a keyboard, a mouse, a camera and a card it only reads. Built directly on the hardware (with Circle), the whole system is small enough to reason about, starts in about two seconds, and has no network stack to remove: there never was one.

Why JavaScript?

So that apps are easy to write, and easy to read. Code that handles your keys should be readable by as many people as possible, and many people read JavaScript. QuickJS is a small engine with modern JavaScript; the heavy and sensitive work (hashes, HMAC, secp256k1 signatures) is native code underneath. Each app's hash covers every line of JavaScript it runs.

Is it audited?

Not by people yet. An independent review by an AI has been done, and fixes for what it found are in progress. Human reviewers are very welcome: the code is on GitHub, and security problems can be reported privately (SECURITY). Until GapKeep has had more eyes on it, be cautious with what you trust it with.

Does it work without the camera?

Mostly, yes. Everything you bring in can be typed: codex32 shares, seed words, authenticator keys. Results are on the screen. The Signer, though, reads transactions as QR codes, so it needs the camera; that is why the camera is highly recommended.

Which wallets work with the Signer?

Electrum, today: it makes the transaction and shows it as a QR code, and it reads the signed one back from GapKeep's screen. For transactions too large for one code, the Signer shows animated BBQr codes, the multi-part format Coldcard and Sparrow use (Electrum doesn't read BBQr). A companion web wallet, GapWallet, is coming. Details in the Signer's documentation.

Can I write my own app?

Yes, and that is the point. Open the browser IDE, start from an example, and run it. When it's ready, export it and copy it to the apps folder of a card: the launcher shows its hash. Start with Writing apps; with an AI agent, the guide for agents.

Can I use it today?

It runs on real hardware, and every test scenario passes on a Pi Zero. But it is new: SD card images are not published yet (you can build one from source), and the code needs more review. Try it, break it, tell us; keep real money on tools with a longer record for now.
