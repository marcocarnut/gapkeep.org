SD card images

Two images, ready to write to a microSD card for a Raspberry Pi Zero v1.3. They differ only in the language GapKeep starts in; either can be switched to the other in the Settings app (until power-off) or in gapkeep.txt on the card.

Not published yet.The first images will be attached to a GitHub release, with their hashes, and listed here. Until then you can build a card from source, or try GapKeep in your browser.

  1. Check the download

    Compare the file's SHA-256 with the one published on the release page (and in its SHA256SUMS file) and on this page. They must be identical, every character.

    Linux

    sha256sum gapkeep-*.img*

    macOS

    shasum -a 256 gapkeep-*.img*

    Windows (PowerShell)

    Get-FileHash .\gapkeep-*.img* -Algorithm SHA256

  2. Write it to a card

    The simplest way is Raspberry Pi Imager: choose Use custom as the operating system, pick the image, then the card. Skip its customisation settings: GapKeep has no use for Wi-Fi or user accounts. Any tool that writes disk images works (balenaEtcher, GNOME Disks).

    On Linux or macOS, dd does it too. Find the card's device name first (lsblk on Linux, diskutil list on macOS): writing to the wrong device destroys what is on it.

    sudo dd if=gapkeep-en.img of=/dev/sdX bs=4M conv=fsync status=progress

    Then put the card in the Zero, connect the screen, the keyboard (port USB) and power (port PWR). The launcher is up in about two seconds; from then on, the card can be taken out.

  3. Check what runs

    A checked download only proves the file is the one published. GapKeep also lets you check what it runs, on its own screen:

    • The kernel's hash: in the launcher, press i for the system information, with the SHA-256 of the running kernel's code.
    • Each app's hash: at the bottom of the launcher, for the selected app. It covers every file of the app, so every line of code it runs.
    • Reproducible builds: with the pinned compiler, the same commit gives the same kernel.img, byte for byte, wherever it is built. Anyone can rebuild a release and compare (tools/check_reproducible.sh; see Building).

  4. Where the hashes are published

    With each release on GitHub: the images' SHA-256 and, to compare with your screen, the hashes of the kernel and of the apps they hold. This page repeats the images' hashes; if the two ever differ, trust neither, and tell us.
