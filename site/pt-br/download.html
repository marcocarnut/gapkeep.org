Imagens para cartão SD

Duas imagens, prontas para gravar num cartão microSD para o Raspberry Pi Zero v1.3. A única diferença é o idioma em que o GapKeep inicia; dá para trocar um pelo outro no aplicativo Configurações (até desligar) ou no arquivo gapkeep.txt do cartão.

Ainda não publicadas.As primeiras imagens serão anexadas a uma versão no GitHub, com os seus hashes, e listadas aqui. Até lá, você pode montar um cartão a partir do código (em inglês), ou experimentar o GapKeep no navegador.

  1. Confira o download

    Compare o SHA-256 do arquivo com o publicado na página da versão (e no seu arquivo SHA256SUMS) e nesta página. Eles têm de ser idênticos, caractere por caractere.

    Linux

    sha256sum gapkeep-*.img*

    macOS

    shasum -a 256 gapkeep-*.img*

    Windows (PowerShell)

    Get-FileHash .\gapkeep-*.img* -Algorithm SHA256

  2. Grave no cartão

    O jeito mais simples é o Raspberry Pi Imager: escolha Use custom como sistema operacional, selecione a imagem e depois o cartão. Pule as opções de personalização: o GapKeep não usa Wi-Fi nem contas de usuário. Qualquer programa que grave imagens de disco serve (balenaEtcher, Discos do GNOME).

    No Linux ou no macOS, o dd também resolve. Antes, descubra o nome do dispositivo do cartão (lsblk no Linux, diskutil list no macOS): gravar no dispositivo errado destrói o que estiver nele.

    sudo dd if=gapkeep-pt-BR.img of=/dev/sdX bs=4M conv=fsync status=progress

    Depois, coloque o cartão no Zero e ligue a tela, o teclado (porta USB) e a alimentação (porta PWR). O lançador aparece em uns dois segundos; a partir daí, o cartão pode ser retirado.

  3. Confira o que roda

    Um download conferido só prova que o arquivo é o publicado. O GapKeep também deixa você conferir o que ele executa, na própria tela:

    • O hash do kernel: no lançador, aperte i para ver as informações do sistema, com o SHA-256 do código do kernel em execução.
    • O hash de cada aplicativo: no rodapé do lançador, para o aplicativo selecionado. Ele cobre todos os arquivos do aplicativo, ou seja, cada linha de código que ele executa.
    • Compilações reproduzíveis: com o compilador fixado, o mesmo commit gera o mesmo kernel.img, byte a byte, onde quer que seja compilado. Qualquer pessoa pode recompilar uma versão e comparar (tools/check_reproducible.sh; veja Building, em inglês).

  4. Onde os hashes são publicados

    Junto com cada versão no GitHub: o SHA-256 das imagens e, para comparar com a sua tela, os hashes do kernel e dos aplicativos que elas contêm. Esta página repete os hashes das imagens; se um dia os dois forem diferentes, não confie em nenhum, e avise a gente.
