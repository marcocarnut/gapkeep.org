GapKeep JavaScript API reference

<!-- Generated by tools/gen_api.py from docs/api/gapkeep-api.yaml - edit that, not this. -->

Apps are ES modules running on QuickJS. They reach the system through the modules below, imported by name:

Module Available to Purpose
gk:ui every app (the e-paper panel: "epaper") Widgets, layout, input, alerts; an e-paper panel
gk:sys every app App info, versions, uptime, memory, exit
gk:crypto every app Hashes, HMAC, PBKDF2, secp256k1 (ECDSA, Schnorr, BIP-32 and Taproot tweaks), OpenPGP's Ed25519, X25519, RSA signatures and decryption, AES-CFB, key wrap, S2K and message decryption, hardware random bytes
gk:clock every app (setting it: "rtc") The wall clock, alarms on its marks
gk:session every app Values kept across the app's runs, in RAM, until power-off
gk:i18n every app (changing the settings: "settings") Translations, numbers, amounts and dates in the person's language
gk:data every app (only the folders its manifest lists in "data") Read-only files from the card's data folders, shared by name
gk:usb apps that list devices in "usb" (only those) Control transfers to USB devices claimed for them
gk:zlib every app Decompression (DEFLATE, zlib), with a limit on the output
gk:apps apps with the "apps" permission List and launch apps (the launcher)

Plus the globals console, setTimeout, setInterval, clearTimeout and clearInterval, and the standard JavaScript library (ES2023).

An app's own modules are imported with relative paths ("./lib/x.js"). Paths are resolved inside the app's directory; .. cannot leave it.

#Creating widgets

new ui.Label(props?)            // child of ui.screen
new ui.Label(parent, props?)    // child of another widget

props is an object of properties and event handlers. Unknown property names and invalid values throw a TypeError naming the problem, both here and in set(), so typos don't fail silently.

Widgets can be subclassed:

class Title extends ui.Label {
  constructor(parent, text) {
    super(parent, { text, font: 28 });
  }
}

#Widgets

#Container

An invisible box for layout: no background, border or padding, sized to its content by default. Children's focus rings may draw outside it.

A Container doesn't scroll unless you set scrollable: true. A scrollable Container clips its content (rows scrolled out of view must not draw over the rest of the screen) and, unless you set padding, gets 5 px of padding so the focus rings of the widgets at its edges stay whole. If you set your own padding on a scrollable Container, leave at least 5 px for the ring: it is 3 px wide, 2 px away from the widget.

#Panel

A box with the theme's "card" look: background, border, rounded corners, padding, scrollbars when content overflows.

#Label

Text: one line or wrapped; with markup: true, in several styles.

Property Value Notes
text string Readable. May contain \n and ui.symbols. With markup, it is markup (below), and reads back as it was set.
overflow "wrap", "clip", "dots", "scroll", "scroll-circular" What happens when text is wider than the label (set a width for this to matter). With markup: "wrap", "clip" (the first line) or "dots" (set a maxHeight too).
markup boolean Readable. Set when the Label is created (new ui.Label({ markup: true, text }); changing it later throws). Then text is Pango-style markup: <b> and <i> (bold, italic, and both: at every size, drawn from outlines when first used), <tt> (the monospaced font, at the same size), <big> and <small> (the next size of ui.fonts up or down), <u>, <s>, <span> with color ("#RRGGBB" or "#RGB"), size (whole pixels, 8 to 120: ui.fontRange), font_family="monospace", weight="bold", style="italic", underline="single", strikethrough="true"; entities &lt; &gt; &amp; &quot; &apos; &#N; &#xN;. Anything else throws a TypeError that says what and at which character: an unknown tag, bold or italic monospaced text (there is no such font), bgcolor, tags left open or crossed, a bad value, a & that starts no entity. Escape data with ui.escapeMarkup, or build the text with gk:i18n's tm(). Markup.

#QRCode

A QR code, drawn from text or bytes.

Property Value Notes
data string or Uint8Array Encoded content. Text uses the most compact single mode (numeric for digits only, alphanumeric for 0-9 A-Z $%*+-./: and space, otherwise byte mode with UTF-8); a Uint8Array is encoded as raw bytes. Throws RangeError if it doesn't fit.
ecc "L", "M", "Q", "H" Error correction level (default "M"). Never raised automatically, so the symbol is exactly what was asked for.
version number The smallest version to use, 1 to 40 (default 1): a larger one is used only if the data needs it. For a series of codes shown in turn, such as BBQr's, which should all be one version. modules gives the version used: (modules - 17) / 4.
size number Side length in px (default 160), including a 4-module quiet zone. Modules are drawn at an integer scale.
dark, light color Module colors (default black on white).
modules number Read-only. Modules per side of the current symbol (21 for version 1, +4 per version), 0 when empty.

A rejected value (data too long, size too small) throws and leaves the code unchanged. For example, a 24-word SeedQR (96 digits at ecc: "L") is 29×29, a Compact SeedQR (32 bytes at "L") is 25×25.

#Image

A picture from pixels the app supplies (GapKeep decodes no image formats).

Property Value Notes
src { width, height, data } data: a Uint8Array or ArrayBuffer of width * height * 4 bytes, RGBA with straight alpha, rows top to bottom (as canvas ImageData). Up to 1024 px a side. Copied: the app may reuse its buffer. sys.app.image and the image of apps.list() entries are in this form.

The image shows at its own size. Give the widget a width and height to scale it to fit (keeping its aspect ratio); radius rounds its corners.

new ui.Image({ src: sys.app.image, radius: 12 });

#Scanner

The camera's view, and what the kernel recognises in it: the detectors in detect. The app gets what was found (a QR code's contents), never the picture: the kernel draws the view and runs the detectors. Needs "permissions": ["camera"] in the manifest (otherwise the constructor throws). See CAMERA.md.

Property / method Value Notes
detect list of detector names Readable. Required. What to look for: "qr" (QR codes); "qr-color" (experimental: a colour QR code's colour layer, only with experimental = yes in the card's gapkeep.txt, otherwise an unknown name). An unknown name throws, listing those this system has. More detectors (e.g. ArUco markers) will come under new names, each with its own "detect" event fields. May be changed while scanning.
field "center", "full" Readable. What part of the camera's view the scanner sees. "center" (the default): the middle, at full detail: about a 26° view on the Pi camera, best for a code at 30-60 cm or a phone at arm's length. "full": all of the camera's view, with less detail per degree, so codes must be larger in the picture. Changing it restarts a running scanner.
scanning boolean Read-only. Whether the camera is on for this scanner.
start() Turns the camera on again after stop() or an error. Scanning starts by itself when the widget is created.
stop() Turns the camera off. Deleting the widget, or the app ending, does too.
onDetect handler Event "detect". Something was found; kind says what. "qr": bytes (a Uint8Array) is the code's content, the bytes of its segments as encoded, without character set conversion: ECI designators are dropped (not applied), and Kanji-mode segments arrive as Shift JIS bytes; text the same as a string if it is valid UTF-8, else null; fired again only when the content changes, or when the same code comes back after 2 s out of sight, so each part of an animated code arrives once. "qr-color" (experimental): the same code's colour layer, in an event of its own: bytes and text as for "qr", status "ok" with the colours' data in colour, or, after a second of trying, "plain" (no colour layer) or "unreadable", with colour null; a later "ok" for the same code may still follow. With both detectors, a code gives a "qr" event and a "qr-color" one.
onError handler Event "error". The camera could not start or stopped working; reason says why ("no camera", "the camera is in use by another scanner", ...). Scanning has stopped; start() tries again.

The view is 320×240 unless you set width and height; the picture (640×480 for "center") is scaled to fit, and a green outline marks what was just found. One scanner at a time can have the camera.

new ui.Scanner({
  detect: ["qr"],
  onDetect: ({ kind, bytes, text }) => console.log(`${kind}: ${bytes.length} bytes`),
  onError: ({ reason }) => (status.text = reason),
});

#ui.alert

const index = await ui.alert(message, { title, buttons });

Shows a modal dialog over the app. buttons is an array of labels (default ["OK"]). Resolves with the index of the button pressed, or -1 if the person pressed Escape. While an alert is open, Tab moves only between its buttons and ui.onKey handlers are not called. Alerts can be nested.

#ui.onKey

ui.onKey((ev) => { ... return true; });   // or ui.onKey(null) to remove

Called for every key press before it reaches the focused widget. Return true to consume the key. The event has:

Field Description
key Key name (see below).
shift, ctrl, alt Modifier state (booleans).
repeat true if the key is being held down and this press is an auto-repeat (after 400 ms, every 80 ms).

With Ctrl or Alt held, keys are delivered to the handler only, not typed.

#Key names

Printable characters are themselves ("a", "A", "7", " ", "ç"), as the keyboard layout types them (keyboard in gapkeep.txt: us or br-abnt2); an accent typed with a dead key arrives once, composed with the letter ("á"). Others: "Enter", "Escape", "Backspace", "Delete", "Tab" (check shift for Shift+Tab), "ArrowUp", "ArrowDown", "ArrowLeft", "ArrowRight", "Home", "End", "PageUp", "PageDown", "Insert", "F1"..."F9".

The Windows/Super key is reserved: it always returns to the launcher. Shift+PageUp and Shift+PageDown are the system's too: they scroll the focused widget's nearest scrollable ancestor by a page, as the mouse wheel scrolls what is under the pointer, and never reach ui.onKey.

#ui.epaper

An e-paper panel wired to the GPIO header (a WeAct 2.9" black, white and red one, say), which keeps its picture without power, for years: a secret share written on it can be unplugged and put away, never photographed. The panel is a second display, off screen: build what it shows with the same widgets as the screen, then refresh() writes it. Needs "permissions": ["epaper"] in the manifest (otherwise both functions throw a TypeError). The card's gapkeep.txt says which panel is there and on which pins (EPAPER.md).

const panel = ui.epaper.open();             // landscape; throws if there is none
new ui.Label(panel, { text: "Share A", font: 20, color: 0xff0000 });
new ui.QRCode(panel, { data: share, size: panel.height - 8 });
await panel.refresh({ onProgress: (f) => (bar.value = f * 100) });
status.text = "Done: you can unplug the panel.";
Member Description
ui.epaper.info() The configured panel, { model, width, height, colors } (landscape), or null if there is none (none in gapkeep.txt, or no SPI controller, as on QEMU).
ui.epaper.open(options?) Opens it: an EPaperPanel. options: orientation "landscape" (the default: wider than tall) or "portrait", as the person looking at the panel sees it, mounted (gapkeep.txt's epaper_rotate: an app needn't know how it is mounted); flip: true (a half turn more). Throws an Error if there is no panel, a TypeError if it is open already. Opening sends nothing to the panel.
panel A Container, the panel's whole area (width, height readable), white, a column with 4 px padding and gap: put widgets on it as on ui.screen. They are not keyboard targets.
panel.colors ["black", "white"], or with "red".
panel.model The module, for people: "WeAct 2.9\" B/W/R".
panel.refresh(options?) Writes what the widgets show onto the panel: a promise, a long operation (onProgress). Every refresh resets the panel and sets it up again (it may be another panel than last time), writes the picture, plays the panel's own full waveform (18 s on the 2.9" B/W/R: it flashes, then shows the picture, red last) and puts it into deep sleep; then it resolves, and the panel may be unplugged. It rejects with an Error if no panel answers (unplugged), or one stops answering. The picture is taken when refresh() is called. options.signal, an AbortSignal, cancels it: already aborted, the promise rejects at once and nothing is sent; aborted before the refresh command (during the reset, the set-up or the planes), the panel is put into deep sleep (or given a reset, if it was busy) with its picture untouched, and the promise rejects with the signal's reason; aborted after it, the waveform can't be stopped without leaving the pigments part way and its DC balance broken, so it runs to its end and deep sleep, and then the promise rejects.
panel.close() Deletes the panel's widgets and gives the panel back (delete() does the same); what the panel shows stays. A refresh asked for goes on. The panel is closed when the app stops, too.

The panel's widgets are drawn in black on white. Colours become the panel's: red (0xff0000, and colours near it: red at least 128, green and blue under 96) where the panel has red, black where it hasn't; other colours black if darker than a middle grey, white if lighter. Text is drawn without its grey edges: prefer sizes of 16 and up, and the monospaced font for codes.

GapKeep never refreshes or clears a panel unless an app asks. What a panel shows is never logged.

#ui.theme

ui.theme({ dark: true, primary: "#009688", secondary: "#ffc107" });

Changes the theme for widgets created afterwards; call it before building the screen. The secondary color is also the focus ring. The system theme is restored when the app exits.

#Symbols

Icon glyphs from the built-in font, usable inside any text: audio, video, list, ok, close, power, settings, home, download, drive, refresh, mute, volume-mid, volume-max, image, tint, prev, play, pause, stop, next, eject, left, right, plus, minus, eye-open, eye-close, warning, shuffle, up, down, loop, directory, upload, call, cut, copy, save, bars, envelope, charge, paste, bell, keyboard, gps, file, wifi, battery-full, battery-3, battery-2, battery-1, battery-empty, usb, bluetooth, trash, edit, backspace, sd-card, new-line.

#gk:crypto

import * as crypto from "gk:crypto";
Name Description
sha1(data) SHA-1, a Uint8Array(20). Broken for collisions: for HMAC-SHA1 (TOTP) and protocols that require it, not to identify data.
sha256(data) SHA-256 of a typed array (its bytes), an ArrayBuffer, or a string (as UTF-8). Returns a Uint8Array(32). Synchronous.
sha512(data) SHA-512, a Uint8Array(64).
sha224(data) SHA-224, a Uint8Array(28).
sha384(data) SHA-384, a Uint8Array(48).

The hashes' data, and hmac's and pbkdf2's key, password and salt, are typed arrays (their bytes: a subarray hashes just its part), ArrayBuffers, or strings, taken as UTF-8. Hashes, HMAC, PBKDF2 and OpenPGP's S2K run in the kernel (src/crypto, written from FIPS 180-4, the RIPEMD-160 paper, RFC 2104, RFC 8018 and RFC 9580, checked against their test vectors): microseconds per block on a Pi Zero, where the same in JavaScript takes about a millisecond. The copies made of keys and data are overwritten after use.

secp256k1 (Bitcoin's curve) is Bitcoin Core's libsecp256k1 (MIT), whose arithmetic on secrets is constant-time. Its keys, hashes, tweaks and signatures are typed arrays or ArrayBuffers, never strings: 32 bytes for private keys, hashes, messages to sign and tweaks; public keys SEC 1 encoded (33 bytes compressed, 65 not) or, for BIP-340 and Taproot, x-only (32). Wrong types throw a TypeError, wrong sizes and keys that aren't keys a RangeError; the verify and is functions return false instead. BIP-32, addresses and transactions are the app's, in JavaScript on these: e.g. a child key is privateKeyTweakAdd(k, I.slice(0, 32)) with I = hmac("SHA-512", chainCode, data). On a Pi Zero, an ECDSA signature takes about 9 ms, a BIP-32 derivation step under 2 ms, a BIP-39 seed 93 ms.

OpenPGP's primitives: what an OpenPGP app needs natively to make signatures with imported Ed25519 and RSA keys and to unlock protected secret keys; packets, armor, keyrings and the signed data's digest are the app's, in JavaScript. Ed25519 is Monocypher's (4.0.3, CC0 or BSD-2-Clause, constant-time); RSA and AES are Mbed TLS's (3.6 LTS, Apache-2.0: its constant-time bignum, with the private operation blinded and its result checked). Keys, digests, signatures, salts and IVs are typed arrays or ArrayBuffers, never strings (a passphrase may be one, as UTF-8). Wrong types throw a TypeError, wrong sizes and numbers that aren't keys a RangeError, unknown hash names a TypeError; the verify functions return false for signatures and public keys that don't check out.

Private keys are objects (Ed25519PrivateKey, RsaPrivateKey) that keep the key in native memory, out of reach of JavaScript, until destroy() wipes it; else it is wiped when the object is collected, and at the latest when the app exits. The key's bytes do pass through JavaScript once, to make the object (the app decrypts and parses its secret-key packet itself): overwrite those arrays (.fill(0)) once the key is made. Copies JavaScript made on the way (a slice, a string) stay in memory until the collector frees them (the heap is wiped as it frees), so handle key material in as few arrays as you can.

Signing checks its own result: an RSA signature against the public key (twice: Mbed TLS, then GapKeep), an Ed25519 one by verifying it. A wrong result, which a hardware fault could cause and which could reveal the key, is never returned: sign throws an InternalError.

AES runs from lookup tables, which is not constant-time against code sharing the processor's cache; on GapKeep, one app runs at a time, and the key is the app's. On a Pi Zero: an Ed25519 signature takes about 4 ms, its verification 3 ms; an RSA signature 90 ms with 2048 bits, 220 ms with 3072 and 460 ms with 4096 (checks included; the first with a key up to 170 ms more, as its blinding values are made), a verification under 20 ms; importing an RSA key 30 to 90 ms; AES-CFB about 10 MB/s, SHA-256 16 MB/s.

Long operations. What can take more than a quarter of a second on a Pi Zero returns a promise: openpgpS2k, openpgpS2kArgon2, argon2id, pbkdf2Async, seipdV1Decrypt, seipdV2Decrypt, ocbedDecrypt, an RSA key's sign and decrypt, and gk:zlib's inflate. The work is done natively in slices of about 20 ms, one each time round the main loop, between the screen being drawn and keys being read: the app stays responsive (it can show a progress bar, from onProgress; the longest wait between screen updates was 30 ms during the largest S2K and 220 ms during an RSA-4096 signature, whose two halves are one slice each). They run one at a time, in the order they were asked for; at most 16 may wait (a 17th throws a RangeError). Arguments are checked when the call is made (errors are thrown, not rejected). When the app stops (it exits, or the Windows key takes the person home) its operations are dropped and wiped, their promises never settled; when the watchdog (or Ctrl+C) stops one of its scripts, they are rejected with an InternalError. The last argument may be { onProgress, signal }. onProgress: a function called after each slice that moved the work on, with a fraction (more than 0, at most 1). signal: an AbortSignal, to cancel it as on the web (const ac = new AbortController(); crypto.argon2id(..., { signal: ac.signal }); ac.abort();): an operation still waiting is dropped, a running one stops at the end of its slice (Argon2id wipes its memory first, over its next slices), and its state is wiped; the promise rejects with signal.reason, an Error named "AbortError" unless abort(reason) gave another. A signal aborted already rejects at once, nothing started; aborting after the promise settled does nothing. (An e-paper panel's refresh() takes a signal too, but once the panel's waveform has begun it runs to its end, and only then does the promise reject: panel.refresh, above.) pbkdf2 stays synchronous, and so do Ed25519, X25519, verification, key wrap, AES-CFB (at most 2 MiB a call) and importing keys, which are fast at the sizes apps use; and the hashes (below).

Hashing big data. The hashes (sha256(data), ..., hmac, and each update of createHash) take any amount, and block while they hash: on a Pi Zero, about 16 MB/s with SHA-1 and SHA-256, 9 MB/s with SHA-384 and SHA-512 (a 4 MB file: a quarter and half a second). For more than a megabyte or two, feed a hash in pieces of 1 to 2 MiB and let the main loop run between them, so the screen stays alive and the watchdog (10 s per call) is never near:

async function sha256Of(bytes, onProgress) {
  const h = crypto.createHash("SHA-256"), piece = 1 << 20;
  for (let at = 0; at < bytes.length; at += piece) {
    h.update(bytes.subarray(at, at + piece));
    onProgress?.(Math.min(1, (at + piece) / bytes.length));
    await new Promise((resolve) => setTimeout(resolve, 0));	// let the screen be drawn
  }
  return h.digest();
}

Decrypting OpenPGP messages (RFC 9580; what GnuPG makes with its usual settings): the app parses the packets; the public-key encrypted session key packet gives the session key, with an RSA key's decrypt (implicit rejection: always some bytes) or, for ECDH, with x25519PrivateKey, the KDF and aesKeyUnwrap; the app checks the session key's algorithm and checksum, then seipdV1Decrypt, seipdV2Decrypt or ocbedDecrypt (by the packet) decrypts the message and checks its integrity before anything of it is given; a compressed data packet inside goes to gk:zlib. The session key does pass through JavaScript (the app reads its algorithm octet and checksum), as the private key does on import: wipe it (.fill(0)) once used. Keeping it native would need the session key packet parsed natively too (its RSA and ECDH forms, the KDF, the checksum), returning a handle that seipdV1Decrypt takes instead of bytes. GnuPG 2.4 writes its own OCB packet (tag 20, ocbedDecrypt) to keys that announce AEAD, as its own new keys do, and SEIPD v1 to others; RFC 9580 implementations write SEIPD v2 (EAX, OCB or GCM). A passphrase-protected message or key may use Argon2 (S2K type 4): openpgpS2kArgon2, up to a quarter of the board's memory (128 MiB on a Pi Zero).

Each group (RIPEMD-160, PBKDF2, secp256k1, Ed25519, X25519, RSA, AES, S2K, SEIPD, OCB, EAX, GCM, AEAD packets, Argon2id) checks itself against known answers before its first use (RSA's and Argon2id's, in the slices of their first long operation, not at import); if that fails, it throws an InternalError until reboot.

Where the randomness comes from. The BCM2835's hardware random number generator, treated as a noise source of unknown quality. Every raw byte passes NIST SP 800-90B's continuous health tests (Repetition Count and Adaptive Proportion, tuned for an assumed 1 bit of entropy per byte), 4096 bytes are tested at boot, and each 32 output bytes are SHA-256 of 256 raw bytes. If a test ever fails, the generator shuts off until reboot: randomBytes and getRandomValues then throw an InternalError, and never return weak bytes.

The hardware RNG is undocumented. Apps handling secrets should treat it as a supplement to entropy the person provides (dice, coins), not a replacement. (In the simulator, the bytes come from the host's random source.)

To run code written for WebCrypto unchanged, give it a small adapter:

import * as gkcrypto from "gk:crypto";
globalThis.crypto = {
  getRandomValues: gkcrypto.getRandomValues,
  subtle: { digest: async (alg, data) => ({ "SHA-1": gkcrypto.sha1, "SHA-256": gkcrypto.sha256,
                                             "SHA-384": gkcrypto.sha384,
                                             "SHA-512": gkcrypto.sha512 })[alg](data).buffer },
};

#gk:clock

import * as clock from "gk:clock";

The wall clock, kept by the system whatever app runs. A Pi Zero has no battery-backed clock, so the time is lost at power-off: until the clock app sets it, it counts from 1970-01-01 at boot (status().set is false). Date.now() and new Date() follow this clock, and local time (getHours(), ...) is UTC plus the clock's fixed offset (no daylight saving rules). Every app may read it; setting it needs "permissions": ["rtc"] (the others throw a TypeError). See CLOCK.md.

#gk:session

import * as session from "gk:session";

Values an app keeps across its runs: leave it, use other apps, come back, and they are still there. Only until the device is switched off: the store is in the kernel's RAM, and nothing is ever written to the card. Each app has its own, which no other app can read, and neither can another version of the app: the store is filed under the app's id and its hash. Up to 64 KiB per app (keys and values), 1 MiB for all.

const accounts = session.get("accounts") ?? [];
// ... the person adds one ...
session.set("accounts", accounts);

Values are copied in and out, as a structured clone: objects, arrays, strings, numbers, booleans, null, BigInts, Dates, ArrayBuffers and typed arrays. Changing a value after set doesn't change what is stored: set it again. Not stored (a TypeError, and the store is left as it was): functions, Map, Set, getters, cycles. Objects come back as plain objects (not their class). A typed array is stored with its whole buffer: store a.slice() rather than a view into a larger buffer.

What is removed, replaced or cleared is overwritten in memory before it is freed. Secrets kept here are still in RAM until power-off: give the person a way to forget them (clear()).

remove(key) Removes the key; false if it wasn't there.

#gk:data

import * as data from "gk:data";

Read-only files the person put on the SD card when preparing it, in data/<folder>/... beside apps/: public keys, address books, word lists. An app reads only the folders its manifest lists, "data": ["pgp"], and nothing can write them. Apps that list the same folder share it. Any kind of file: binary (an exported OpenPGP key) or text (.asc). APPS.md, "Data files" says how to lay them out and put them on a card, or build them into a sealed kernel.

for (const { name, size } of data.list("pgp")) {
  const key = data.read("pgp", name);          // Uint8Array
  // ... parse it, show its fingerprint ...
}

The data is not part of the app's hash. The app hash names the code, and is the same on every card; the data is whatever the card holds, and whoever can change the card can change it. So show the person what matters before using it: for a key, its fingerprint, to be compared with one they trust; hash(folder) names the whole folder, as the launcher shows it.

Every folder some installed app lists is read at boot, all of it, hashed, and kept in memory until power-off; these functions never touch the card, which can be taken out once the launcher is up. What the app reads is what was hashed. Limits: 4 MB per file, 8 MB and 256 files per folder, 32 folders and 32 MB in all. A folder over them, or with a name that is not printable ASCII, is refused at boot: every call on it throws, saying why. Names starting with . (macOS's ._x) are skipped. A sealed build reads no card; its data folders, if any, are built into the kernel and served the same way.

Every refusal is a TypeError that says what is wrong: a folder that is not in the manifest, a path that leaves the folder (.., ., a leading /, a \), a file that isn't there. A folder that isn't there (not on the card; every folder without a card, or in a sealed build without built-in data) has no files: list() returns [] and hash() null.

Name Description
list(folder) The folder's files, { name, size }, sorted by name (byte order): name is the path inside the folder, with / between folders ("keys/alice.asc"), size in bytes. [] if there is no such folder.
read(folder, name) The file's bytes, a fresh copy. name as list() gives it.
readText(folder, name) The file as UTF-8 text. A TypeError if it isn't valid UTF-8 (or holds a NUL byte); read() gives its bytes.
hash(folder) The SHA-256 of the folder's files, 64 hex digits, as the launcher shows it: the app hash's scheme, so tools/bundle_apps.py --data-hash <folder> computes it on a computer. null if there is no such folder.

#gk:usb

import * as usb from "gk:usb";

Control transfers to USB devices the app lists by vendor and product id in its manifest: "usb": ["16c0:27db"] (lowercase hex, at most 8). Importing it without them throws a ReferenceError. A device some available app lists is claimed whole by the system when it is plugged in (those plugged in at boot too): none of its interfaces gets a system driver, so a keyboard or mouse in it is ignored, and what it types never reaches the system. Every app that lists it can use it, as apps run one at a time. Only endpoint 0 is reached: control transfers of at most 64 bytes, each stage given 1 s (ARCHITECTURE.md, "Security model"). After two timeouts a device's transfers fail at once, until it is plugged in again.

usb.onAttach(async (device) => {
  const board = usb.open(device);
  await board.setFeatureReport(2, request);           // HID SET_REPORT
  const answer = await board.getFeatureReport(2, 37);  // HID GET_REPORT
  board.close();
});
for (const device of usb.list()) { /* plugged in already */ }

Transfers are promises: each is queued, and the system does one at a time, between frames, so the screen stays drawn. Arguments are checked at the call (a TypeError or RangeError, thrown); what the device does settles the promise. A rejection is an Error with a code: "stall" (the device refused the request), "timeout", "detached", "closed" (the handle was closed while it waited) or "error" (the bus, or a device that sent more than was asked for). At most 16 wait at once.

The setup of a transfer is { type, recipient, request, value, index }: type "standard", "class" or "vendor"; recipient "device" or "interface" (then index's low byte must be one of the device's interfaces); request 0 to 255; value and index 0 to 65535 (default 0). Of the standard requests only those that read are an app's (GET_STATUS, GET_DESCRIPTOR, GET_CONFIGURATION, GET_INTERFACE, with controlIn): the others change how the system talks to the device.

A handle (open()) has device (as list() gives it) and these methods:

Method Does
controlIn(setup, length) A control transfer reading 1 to 64 bytes. Resolves to a Uint8Array of what came (it may be shorter).
controlOut(setup, data?) A control transfer writing data (a Uint8Array, ArrayBuffer or array of bytes; 0 to 64). Resolves to the number of bytes sent.
getFeatureReport(id, length, iface?) HID GET_REPORT of feature report id on interface iface (default: the first HID interface). Resolves to the data stage as the device sent it: with report ids, most devices put the id first.
setFeatureReport(id, data, iface?) HID SET_REPORT: the data stage is the id (unless it is 0) followed by data, at most 64 bytes in all, as Linux and WebHID send it. Resolves to undefined.
close() Closes the handle; its transfers still waiting reject with "closed".

Nothing a transfer carries is logged: the log has the request's numbers and length when one fails or is refused. In the simulator, devices come over USB/IP (SIMULATOR.md); the browser IDE has none.

Name Description
list() The devices plugged in that the manifest lists: { id, vid, pid, manufacturer, product, serial, speed, interfaces }. id is new each time a device is plugged in; manufacturer and product are what the device says ("" if nothing), with characters that could change how text reads (control, bidi, invisible) as ?; serial likewise, or null; speed "low", "full", "high" or "super"; interfaces [{ number, class, subclass, protocol }] (alternate setting 0 of each).
open(device) A handle on a device of list() or of an event (or its id): { device, controlIn, controlOut, getFeatureReport, setFeatureReport, close }, above. A TypeError if it is not plugged in, not listed, or open already (close() it first).
onAttach(fn) Calls fn with each listed device plugged in while the app runs. Returns a function that removes it.
onDetach(fn) Calls fn with each listed device unplugged. Its handle's transfers fail from then on ("detached"); plugged in again it is a new device, with a new id.

#gk:zlib

import * as zlib from "gk:zlib";

Decompression of DEFLATE data (RFC 1951), raw or in zlib's format (RFC 1950): what OpenPGP's compressed data packets hold (their algorithm 1, ZIP, is raw DEFLATE; 2, ZLIB, zlib's format; BZip2, 3, isn't here), and what other formats use. zlib's own inflate (zlib 1.3.2, zlib License), checked against known answers before its first use and fuzzed (tools/fuzz_inflate.sh).

You must say how big the result may be (maxOutput, at most 32 MiB): a few hundred bytes can decompress to gigabytes, and the limit is checked as the output grows, so such data is refused (a RangeError) with nothing more allocated than the limit allows. Decompression is a long operation (gk:crypto's): a promise, the work done in slices while the screen keeps being drawn, about 1 MiB in 0.1 s on a Pi Zero. Data that isn't valid in the format, is cut short, or has more after its end rejects with an Error. What it decompresses is wiped from native memory when done.

Name Description
inflate(data, { format, maxOutput, onProgress, signal }) A promise of data (at most 8 MiB, copied when the call is made) decompressed: format "raw" (DEFLATE) or "zlib", maxOutput the most bytes it may decompress to, 1 to 33,554,432 (32 MiB). Missing or wrong options throw at once (a TypeError or RangeError).
