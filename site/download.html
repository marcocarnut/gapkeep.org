SD card images

Two images for a Raspberry Pi Zero v1.3, ready to put on a microSD card. They differ only in the language GapKeep starts in (the Brazilian Portuguese one also uses the ABNT2 keyboard layout); either can be changed in the Settings app, until power-off, or in gapkeep.txt on the card.

Not published yet.The first images will be attached to a GitHub release, with their hashes, and listed here. Until then you can build a card from source, or try GapKeep in your browser.

All releases, with their hashes, on GitHub → · SHA256SUMS · RELEASE.txt

  1. What's in a release

    Each release on GitHub has, for each language (en or pt-BR):

    • gapkeep-<version>-<lang>.img.zip: the image, to write to a card with one of the tools below.
    • gapkeep-<version>-<lang>.zip: the card's files, for the even simpler way: copying them onto a FAT32 card.

    And, for the whole release, SHA256SUMS (the hash of every file) and RELEASE.txt (the GapKeep commit, and the kernel and app hashes the launcher shows).

  2. Check the download

    Before writing anything, check that the file is the one published: compute its SHA-256 and compare it with SHA256SUMS on the GitHub release. They must be identical, every character.

    Windows

    certutil -hashfile gapkeep-1.0-en.img.zip SHA256

    or, in PowerShell:

    Get-FileHash .\gapkeep-1.0-en.img.zip

    macOS

    shasum -a 256 gapkeep-1.0-en.img.zip

    Linux

    sha256sum -c --ignore-missing SHA256SUMS

    in the folder with the download and SHA256SUMS: it should say OK.

    (1.0 stands for the version you downloaded.)

  3. Write it to the card

    Pick one way. Writing an image erases everything on the card.

    The easiest, on Windows, macOS and Linux: Raspberry Pi Imager

    The official, free tool from Raspberry Pi: raspberrypi.com/software.

    1. Choose OS → Use custom, and pick the .img.zip you downloaded (no need to unzip it).
    2. Choose storage: your microSD card.
    3. Write. If it offers to customise the OS (Wi-Fi, user name and so on), skip it: those settings don't apply to GapKeep.

    Also on all three: balenaEtcher

    Free, from etcher.balena.io.

    1. Flash from file, and pick the .img.zip.
    2. Select target: your microSD card.
    3. Flash! It checks the card after writing.

    On Linux, with nothing to install

    • GNOME Disks ("Disks" in most distributions): unzip the image, select the card on the left, then, in the menu, Restore Disk Image… and pick the .img.
    • Linux Mint: its USB Image Writer (mintstick) writes an unzipped .img to the card.
    • For the experienced: dd. Unzip, find the card's device name, and write: 
      unzip gapkeep-1.0-en.img.zip
lsblk                      # find the card: /dev/sdX or /dev/mmcblk0
sudo dd if=gapkeep-1.0-en.img of=/dev/sdX bs=4M conv=fsync status=progress

      Check the device name twice.dd overwrites whatever you point it at, without asking: give it your computer's disk instead of the card and that disk is gone. Compare the size lsblk shows with your card's, and unmount the card's partitions first.

    On macOS

    Raspberry Pi Imager or balenaEtcher, as above.

    Even simpler: copy the files

    GapKeep's card is just files on a FAT32 card, so you can skip the image altogether:

    1. Format the card as FAT32. Cards over 32 GB come formatted as exFAT, and need FAT32 too. Raspberry Pi Imager can do it (Choose OS → Erase, which formats as FAT32), or your system's disk utility.
    2. Unzip gapkeep-<version>-<lang>.zip and copy everything in it to the top of the card.
    3. Eject the card properly before taking it out.

  4. First boot

    Put the card in the Zero, connect the screen (mini-HDMI) and the keyboard (the port marked USB, through the OTG adapter), then power (the port marked PWR). You'll see the Pi's rainbow screen first; about 12 seconds after power-on, most of it the Pi's own firmware, the launcher is up. From then on, the card can be taken out and kept somewhere else.

  5. Check what runs

    A checked download proves the file is the one published. GapKeep also lets you check what it is running, on its own screen, against RELEASE.txt:

    • The kernel: press i in the launcher for the system information, with the SHA-256 of kernel.img (the same as sha256sum kernel.img).
    • Each app: its SHA-256 is at the bottom of the launcher when its tile is selected. It covers every file of the app, so every line of code it runs.
    • Reproducible builds: with the pinned compiler, the same commit gives the same kernel.img, byte for byte, wherever it is built, so anyone can rebuild a release and compare (tools/check_reproducible.sh; see Building). The release images themselves are reproducible too: tools/check_reproducible.sh --release.

    These are a genuine kernel's hashes: a tampered kernel can show any hash. To check a card you don't trust, hash its files on a trusted computer.

    If a hash ever differs from the published one, don't use that card, and please tell us.
